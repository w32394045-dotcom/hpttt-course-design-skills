- id: f01
  title: 关注目标而非行为
  type: framework
  source_chapter: 第七章·课程设计的底层逻辑·关注目标，而非行为
  source_quote: |
    大家只有2%的执行情况不一样，却得到了100%不同的结果……之所以你与其他学员在成绩上的差距如此之大，就是因为一开始你关注的是行为，不是目标。如果关注的是100%命中目标，你就会想，哪些动作是必须完成的。

    该讲时，回到目标自然有答案，目标甚至会反过来修正主题本身。
  tags: [decision, goal-orientation, course-design]

- id: f02
  title: 关注关键工作而非全部工作（杠杆点定位）
  type: framework
  source_chapter: 第七章·课程设计的底层逻辑·关注关键工作，而非全部工作
  source_quote: |
    关注学员做什么，也不是关注他们全部的工作，而是关注他们最关键的工作，即对绩效影响最大的工作。……在这个聚焦的前提下，我又去找到底哪些工作是达成沟通目标的关键点，即杠杆点。
  summary: |
    面对宽泛主题时，逐层聚焦：先澄清真实需求对象（管理者与下属的沟通），
    再深挖其中最关键的问题（不会批评），最后锁定杠杆点设计内容。
    只教对绩效影响最大的关键工作，带来节约时间、简单有效、快速胜任三大收益。
  tags: [decision, leverage-point, focus]

- id: f03
  title: 计划课程四步骤（总流程）
  type: framework
  source_chapter: 第七章·计划课程四步骤
  source_quote: |
    我们往往喜欢从知识点开始设计，但确定学习目标才是重要的一步，也是不可跨越的一步。……整体的计划课程结构包括四个步骤：确定学习目标、罗列知识点、选择关键知识点、撰写课程主题。
  summary: |
    设计一门课的标准流水线：①确定学习目标 → ②MECE罗列知识点 →
    ③三指标选出关键知识点并结构化/模型化 → ④最后才撰写课程主题。
    四步严格串行，前一步是后一步的输入；"定目标"在最前、"写主题"在最后，
    顺序不可跨越。
  tags: [process, course-design, stepwise]

- id: f04
  title: 一句话学习目标逻辑（学习目标 = 工作行为 + 成为的角色）
  type: framework
  source_chapter: 第七章·计划课程四步骤·第一步：确定学习目标
  source_quote: |
    建议初学者使用一句话学习目标的逻辑……按照"学习目标 = 工作行为 + 成为的角色"的逻辑，可举例为"理解培训师核心理念，熟练运用教学循环圈（工作行为），成为一名卓越培训师（成为的角色）"。
  summary: |
    把模糊的教学意图收敛为一句话公式的推理方法：先说清学员课后要能做的工作
    行为，再说清要成为的角色。另一条路径是收益逻辑（观—为—得，见第五章）。
    公式化目标让后续所有内容取舍有了统一判据。
  tags: [goal-setting, formula, course-design]

- id: f05
  title: MECE 罗列知识点（穷尽 / 独立 / 衔接）
  type: framework
  source_chapter: 第七章·计划课程四步骤·第二步：罗列知识点
  source_quote: |
    首先是穷尽，把所有可能的知识点都罗列出来，而不是有选择地进行筛选；其次是独立，各个知识点之间边界清晰，互不交叉与重叠；最后是衔接，既要保持课程知识点的独立性，又要厘清它们的关系，使之具有逻辑性。
  summary: |
    整理内容先穷尽后筛选的思考结构：用头脑风暴+明星员工参与，从老鹰视角
    看全貌避免遗漏；要求相互独立不重叠；作者额外加第三条"衔接"——厘清
    知识点之间的关系使之有逻辑。经典 MECE 在内容罗列场景的扩展版。
  tags: [mece, mental-model, enumeration]

- id: f06
  title: 知识点颗粒度与课程时间匹配（颗粒度的相对性）
  type: framework
  source_chapter: 第七章·计划课程四步骤·第二步：罗列知识点·知识点颗粒度
  source_quote: |
    但不是说课程知识点的颗粒度越小越好，知识点颗粒度具有相对性，在课程主题和课程目标非常明确的前提下，知识点颗粒度与课程时间有非常大的关系。在选择知识点颗粒度时，需要遵循四大原则之一"少就是多"。
  summary: |
    判断内容拆分粗细的决策规则：颗粒度无绝对好坏，取决于可用时间——
    时间短配大颗粒，时间足配细颗粒；时间不够就砍颗粒只讲最重要的一个。
    "少就是多"：讲完≠学会，听过会忘记，做过才掌握。
  tags: [decision, granularity, less-is-more]

- id: f07
  title: 固化/流程类知识点的特殊处理（流程例外分支）
  type: framework
  source_chapter: 第七章·计划课程四步骤·第二步：罗列知识点·固化的知识点或流程类的知识点
  source_quote: |
    如果是固化的知识点，如法律法规等，建议完整地走完计划课程四步骤……课堂上只讲解最关键的知识点，其他知识点可以通过读书打卡的方式来完成；如果是流程类的知识点，那么可以不走选择关键知识点这一步。
  summary: |
    应用标准流程前先按内容类型分支的 if-then 判断：固化内容（法规）→
    仍走完整四步骤，但非关键点移到课后（混合式学习）；流程类内容 →
    跳过"选关键知识点"步骤，直接按教学设计逻辑设计。防止把流程当教条。
  tags: [if-then, boundary, process-adaptation]

- id: f08
  title: 二八定律选关键知识点
  type: framework
  source_chapter: 第七章·计划课程四步骤·第三步：选择关键知识点
  source_quote: |
    通常情况下，每个课程都有十几个甚至更多的可以讲授的知识点。最关键或最能代表岗位水平的只是其中少数的几个关键知识点。根据二八定律，我们要从众多知识点中找到20%的可以达成80%学习目标的知识点。
  summary: |
    内容收敛的核心心智模型：任何一门课可讲的内容中，只有约 20% 能达成
    80% 的学习目标；设计者的任务不是"全讲"，而是找到这关键的少数。
    关键知识点一般不超过 6 个，最多不超过 8 个。
  tags: [mental-model, pareto, prioritization]

- id: f09
  title: 三指标打分法（重要性/难度/频率 × 权重，单项排序）
  type: framework
  source_chapter: 第七章·计划课程四步骤·第三步：选择关键知识点
  source_quote: |
    对罗列出来的所有知识点进行单项指标评价，而不是综合指标评价……得出所有知识点在重要性指标下的排序。如果有12个知识点，就从1到12进行排序……可以加上权重系数。例如：重要性（×3）难度（×3）频率（×1）。
  summary: |
    不凭感觉选重点的量化决策流程：①对全部候选项按单一指标分别排序
    （避免综合评估的认知混乱）；②三个指标用统一的排序方向；③按优先级
    给指标加权重系数；④排序值×权重求总分，总分最高者胜出。
    三个指标各有精确定义：重要性=对绩效及对其他任务的影响；
    难度=内容间相对难度（非对某人）；频率=既定时间段内执行次数。
  tags: [decision, scoring, prioritization, quantitative]

- id: f10
  title: 知识点结构化/模型化四方式（字母 / 流程步骤 / 内容逻辑 / 公式）
  type: framework
  source_chapter: 第七章·计划课程四步骤·第三步：选择关键知识点（结构化部分）
  source_quote: |
    将知识点结构化或模型化，不仅方便学员记忆，而且方便培训师讲授。对课程知识点的结构化，主要通过以下四种方式进行：使用字母结构化并赋予字母意义；按照流程步骤结构化；按照内容逻辑结构化（金字塔）；使用公式结构化。
  summary: |
    把选出的关键知识点串成易记易讲模型的四条路径：
    ①字母式（SMART、GAPS、HAND——字母最好自带意义钩子，如 GAPS=差距）；
    ②流程步骤式（以时间轴为线索，如四步曲，符合人脑记忆逻辑）；
    ③内容逻辑式（金字塔：顶层简单易懂再层层深入，如七个习惯）；
    ④公式式（如"绩效=有价值的结果/行为"，复杂定义清晰化）。
    书中未给出显式选择标准，案例暗示"跟内容特性走"。
  tags: [modeling, structuring, mental-model, memorability]

- id: f11
  title: 结构化必须锚定课程目标（目标校验）
  type: framework
  source_chapter: 第七章·计划课程四步骤·第三步：选择关键知识点（公式结构化·五行修心路案例）
  source_quote: |
    他们关于五行的讨论和争论与课程目标的关系并无关联，与课后的应用也无任何关系。……我建议他们根据当时设定的课程目标，即课程设计四步骤的第一步，看一看是否有问题。果不其然，他们发现他们后面设计的内容与课程目标是不一致的。
  summary: |
    对任何结构化/模型化成果的校验规则：模型再精妙（如五行学说），若与
    课程目标无关就是花架子。检验方法是回到第一步的目标逐一对照；
    发现不一致就简化重构（"客服五行修心路"最终被改为公式
    "超越五星客服 = 人 + 流程"）。结构化必须服务目标，而非炫技。
  tags: [validation, goal-alignment, modeling]

- id: f12
  title: 课程主题命名三点式（痛点 / 焦点 / 利益点）
  type: framework
  source_chapter: 第七章·计划课程四步骤·第四步：撰写课程主题
  source_quote: |
    好的主题应当符合三点式要求：1．直击痛点……2．找到焦点……3．切入利益点。……这是最后要考虑的问题，而不是一开始要考虑的问题。因为经过这四个步骤的分析，最初那个课程主题已经面目全非。
  summary: |
    给内容命名的决策框架：命名放在设计流程最后（此时原主题已面目全非，
    需重新定位），并按三条路径选择切入点——直击痛点（学员的痛）、
    找到焦点（痛点利益点不明确但内容重要时，让人一目了然）、
    切入利益点（用收益抓兴趣）。
  tags: [naming, communication, framing]

- id: f13
  title: 快速胜任而非胜任（课程价值标尺）
  type: framework
  source_chapter: 第七章·课程设计的底层逻辑·关注关键工作，而非全部工作·快速胜任而非胜任
  source_quote: |
    针对同样一门课程，如果你可以达到快速胜任这门课程的目的，就比胜任这门课程本身还有价值。……追求敏捷性的目的是减少学员学习的代价，尽快实现教学目标，而不是单纯地以追求敏捷性为目的。
  summary: |
    评估课程/内容设计价值的思考结构：真正的价值不是"让人胜任"，
    而是"压缩到达胜任的时间"（销售 4 年路径 vs 500 强 3 个月路径）。
    敏捷是手段不是目的——减少学员学习代价、尽快实现目标才是目的；
    只有敏捷没有效果，敏捷就失去意义。
  tags: [mental-model, value-criterion, learning-design]

# 课程主题命名三点式

## 交付物

3-5 个候选课名（每个标注抓的是哪一点）+ "名实一致"与"吸引眼球"两条检验结论 + 由用户选定。

命名时机未到时，产出标为 **【暂定代号 · 未经验证】**，并附一行说明倒推内容的代价。

## 完成判据（交稿前逐条核对）

- [ ] 命名时机三项检查**逐项给出结论**：学习目标可一句话说出？关键知识点已选定？课程结构/模型已定？
- [ ] 明确主题类型（痛点式 / 利益式 / 焦点式）并说出依据
- [ ] 候选名 **3-5 个**（不多不少），每个标注抓的是哪一点
- [ ] **分别**给出"名实一致"与"吸引眼球"两条检验结论，各附依据
- [ ] 最终选择权交给用户，不替用户拍板
- [ ] 时机未到时代号已标注为非正式

## 执行步骤

当 skill 被激活后, agent 应按以下步骤执行。

> **「暂定代号」规则**：命名时机未到而用户仍要名字时，给 3 个**暂定代号**，逐个标注"未经验证的代号，内容定了要重起"，并用一行说明倒推内容的代价。这样既交付了用户要的东西，也不让代号冒充正式课名。

1. **确认命名时机成熟** 🛑 STOP
   - 检查：学习目标可一句话说出？关键知识点已选定（≤8 个）？课程结构/模型已定？
   - 三项全过 → 进第 2 步正式命名；任一项未定 → 说明"先起名会被名字绑架内容"（减肥课反例），按「暂定代号」规则交付
   - 完成标准: 三项检查全通过，或已交付标注清楚的暂定代号

2. **判断主题类型（三选一）** 🔴 CHECKPOINT
   - 问："学员对这门课的内容，有明确的痛吗？" → 有 → 痛点式
   - 没有痛点，问："学好这个对学员的钱/晋升/业绩有直接好处吗？" → 有 → 利益式
   - 都不突出 → 焦点式（让内容一目了然）
   - 完成标准: 明确主选类型，并能说出依据

3. **按类型生成候选名 (3-5 个)**
   - 痛点式: 戳中具体痛处 + 暗示改变（"小改变 → 大结果"的反差尤佳）
   - 利益式: 利益具象化（数字、身份、结果）+ 方法暗示
   - 焦点式: 主标题给画面感（比喻/拟人）+ 副标题说清楚内容（"数据会说话：数据分析与应用"结构）
   - 完成标准: 每个候选都能说出"它抓的是哪一点"

4. **目标一致性终检** 🛑 STOP · 不过则回炉
   - 拿候选名对照学习目标：名字承诺的，课程能兑现吗？名字吸引来的人，是目标学员吗？
   - 好莱坞检验：够吸引眼球吗？能激发兴趣吗？
   - 🛑 判停条件: 名不副实（名字 > 内容）→ 降级夸张成分；名实不符（名字指向偏离目标）→ 回第 3 步
   - 完成标准: 候选名交用户选定后，方可作为定稿；不得替用户直接拍板

### 异常 fallback 速查 (if X 失败 → Y)

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 命名时机未到（目标/关键知识点/模型任一项未定） | 回 `plan-course-4-steps` 对应步骤补齐 | 按「暂定代号」规则给 3 个代号并标注非正式，交付不等工 |
| 用户坚持"先给名字，我再倒推内容" | 说明会被名字绑架内容，用减肥课反例说明代价 | 按「暂定代号」规则给 3 个代号 + 一行代价说明 |
| 三点式都套不上（无痛点、无利益关联、内容也不聚焦） | 回到内容本身找焦点，用"主标题给画面感 + 副标题说清内容" | 用直白描述式课名（如"XX 实务：从 A 到 B"），不做噱头，不做作 |
| 用户把候选名全否了却说不出理由 | 追问"你否掉的是哪一点"（痛点不准/利益不实/画面不对），按类型重出 3 个 | 换类型重来（痛点式→利益式），不要在同一类型里反复微调 |
| 名不副实（名字承诺 > 课程能兑现） | 降级夸张成分，砍掉做不到的承诺 | 回第 3 步重新生成；**禁止靠改课程内容去迎合名字**（那就是被名字绑架） |

## 什么时候不要用这个 skill

- **课程内容还没设计** — 命名是最后一步；先起名会让内容被名字绑架（减肥课学员若不改主题，就会继续讲违背"健康"目标的内容）
- **内部例行培训且无需招生** — 三点式解决"吸引"问题；强制参加的合规培训，清晰大于吸引
- **给内容模型起名** — 模型名用意义钩子逻辑（knowledge-modeling），不是三点式

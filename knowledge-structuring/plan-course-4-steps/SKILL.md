# 计划课程四步骤

## 交付物

一份课程设计方案，含五件：① 一句话学习目标 ② MECE 知识点清单 ③ 关键知识点打分表 ④ 课程模型 ⑤ 课程名（3-5 个候选）。

未获用户确认学习目标前，整份标为 **【草案 · 目标待确认】**；确认后才改称 **【定稿】**。标题里的"草案/定稿"必须与目标的确认状态一致。

## 完成判据（交稿前逐条核对，任一不过就地修好再交）

- [ ] 学习目标写成一句话，含明确工作行为与角色，不含"了解/理解/掌握知识"类纯认知动词
- [ ] 知识点清单 10-20 条，每条有唯一编号，通过穷尽 / 独立 / 衔接三查
- [ ] 打分表**每格已填**（重要性 / 难度 / 频率 + 总分 + 名次），无空单元格、无占位符
- [ ] 关键知识点 ≤8 个，并写明截取线与被砍项
- [ ] 模型有名字，且写出选择地图诊断结论（1 主选 + 1 备选及理由）
- [ ] 课程名 3-5 个候选，每个与第 1 步的学习目标一致
- [ ] 时间账闭合：各段落时长之和 = 课程总时长
- [ ] 目标 → 关键知识点 → 课名 三者互指一致

## 执行步骤

当 skill 被激活后, agent 应按以下步骤执行。

> **「草案」规则（贯穿全程）**：未获用户确认前，产出物一律称**草案**，并在开头一行写明所采用的假设；第 1 步的学习目标被明确确认后，才改称**定稿**。
> 用户说"别问了，直接给我成品"时，照常交付，整份标为 `【草案 · 目标待确认】`，开头写明假设目标，结尾附「待确认清单」。草案本身就是合法交付物——用"草案"这个词即可，不必在"成品"和"不能做"之间二选一。

1. **澄清课程目标（不可跨越）** 🔴 CHECKPOINT
   - 问用户："这门课希望学员学完后**做什么**（不是知道什么）？成为什么样的人？"
   - 用一句话逻辑写出：学习目标 = 工作行为 + 成为的角色
   - 完成标准: 一句话写着，含明确工作行为、含角色，且不含"了解/理解/掌握知识"类纯认知动词
   - 🔴 CHECKPOINT: 把这句话念回用户并拿到明确确认，再进第 2 步
   - 用户说不清目标时：用"你希望学员健康还是漂亮"式二选一帮其收敛
   - 用户拒绝确认时：取最可能的一个目标写成假设，按「草案」规则继续走完四步

2. **MECE 罗列知识点**
   - 先引导用户穷尽罗列，筛选留到第 3 步；建议头脑风暴，条件允许时邀请相关岗位的明星员工参与
   - 三要求逐一核过：穷尽（没有遗漏）/ 独立（边界清晰不重叠）/ 衔接（关系有逻辑）
   - 完成标准: 清单通过三要求检查，通常 10-20 条，且每条有唯一编号

3. **选择关键知识点 + 结构化**
   - 调用 `key-knowledge-filter` 得到打分表，收敛到 ≤6 个（最多 8 个）🔴 CHECKPOINT（打分表与权重摆给用户看）
   - 调用 `knowledge-modeling` 得到模型，并带回它的**选择地图诊断结论**（1 主选 + 1 备选及理由）与逐要素目标校验结论
   - 完成标准: 手上同时有"≤8 个关键知识点 + 打分表 + 一个带名字的模型 + 选择地图结论"四样，缺一样算未完成

4. **撰写课程主题（最后一步）**
   - 调用 `course-title-naming` 得到 3-5 个候选名，由用户选定
   - 完成标准: 主题符合痛点/焦点/利益点之一，且与第 1 步的学习目标一致
   - 🔴 CHECKPOINT: 命名后回头对照第 1 步的学习目标；不一致说明目标已漂移，回第 1 步重走

**交稿前自检（三项一次过）**
- 目标 → 关键知识点 → 课名 三者互指一致
- 时间账闭合：各段落时长之和 = 课程总时长
- 编号与分类连续、无错位
完成标准: 三项全过；任一不过，就地修好再交。

## 什么时候不要用这个 skill

- **课程已成熟，只缺教学呈现设计** — 四步骤是"课程设计"（科学），不是"教学设计"（艺术）；已有内容要讲得更精彩，用成人教学设计八段锦
- **目标是知识普及而非行为改变** — 本流程强绑定"以绩效为基础"，纯兴趣讲座不必动用
- **时间不允许走完流程的救急场景** — 四步骤是严谨流程，明天就要讲课时只能借用第 1 步（定目标）保命

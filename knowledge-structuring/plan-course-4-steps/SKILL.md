# 计划课程四步骤

## R — 原文 (Reading)

> "我们首先应当确定学习目标。这个步骤往往为我们所忽略，以至于我们为了培训而培训的现象时有发生。确定学习目标是非常重要的一步，也是不可跨越的一步，因为方向比努力更重要。"
>
> — 王志刚, 第七章「计划课程四步骤·第一步」

---

## I — 方法论骨架 (Interpretation)

课程设计是科学不是艺术——它有一条不可跳跃的流水线：

**两条底层逻辑（先立住，再动手）：**
1. **关注目标，而非行为**：射击案例中，学员只漏了"拿稳枪"一个动作（2% 的执行差异），成绩却是 0 分对 100 分（100% 的结果差异）。设计课程同理：目标是选择一切内容的判据，纠结"这个要不要讲"时，回到目标就有答案——目标甚至会反过来修正课程主题。
2. **关注关键工作，而非全部工作**：只教对绩效影响最大的少数关键工作。价值标尺是"快速胜任"——不是让学员学会，而是让学员用最短时间上岗。

**四个步骤（严格串行）：**
1. **确定学习目标** — 用一句话逻辑：学习目标 = 工作行为 + 成为的角色（如"熟练运用教学循环圈，成为一名卓越的培训师"）
2. **罗列知识点** — MECE 穷尽罗列，此步禁止筛选（详见 key-knowledge-filter）
3. **选择关键知识点** — 三指标打分收敛到 ≤6 个（详见 key-knowledge-filter），并结构化成模型（详见 knowledge-modeling）
4. **撰写课程主题** — 最后才命名，因为走完三步后主题已面目全非（详见 course-title-naming）

## A1 — 书中的应用 (Past Application)

### 案例 1: 从"沟通技巧"到"批评的沟通艺术"
- **问题**: 作者接到一个"沟通技巧"培训需求——主题宽泛、学员已听过无数类似课程
- **方法论的使用**: 不断澄清需求，发现真正问题是管理者与下属的沟通；继续深挖，发现这些技术出身的管理者惧怕冲突、不敢批评人——于是聚焦到"批评的沟通艺术"，再找达成目标的关键工作（杠杆点）设计课程模型
- **结论**: 宽泛主题必须收敛到关键工作中的最关键问题，课程才有抓手
- **结果**: 学员反馈"听过很多沟通课，道理都懂但不会用；这次直击痛点，有信心课后运用"

### 案例 2: 减肥课学员的主题改写
- **问题**: 工作坊学员设计"30 天快速减肥"课，认为所有内容都重要、无法取舍
- **方法论的使用**: 作者连续追问目标——"你希望学员健康还是漂亮？""是保持体重还是减肥？"学员发现"吃减肥药"等内容与"健康"目标冲突，且主题与真实目标错位
- **结论**: 目标澄清后，取舍自然发生，连课程主题都改成了生活方式主题
- **结果**: 学员豁然开朗，重新选择了课程内容

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 第一次要开发一门课（内训/分享/工作坊），面对空白文档不知从何开始
2. 业务方丢来一个宽泛主题（"做个沟通培训""搞个领导力课"），需要收敛成可设计的课程
3. 工作坊中，学员抱着一堆素材问"这些我都要讲吗？怎么组织？"
4. 已有课程大纲但逻辑松散，想用科学流程重构一遍

### 语言信号 (用户的话里出现这些就应激活)

- "我想做一门课，怎么开始？"
- "课程内容太多，怎么组织？"
- "帮我搭个课程框架 / 设计一门课"
- "design a course / course structure / 课程设计"
- "为了培训而培训"（批评现状时）

### 与相邻 skill 的区分

- 与 `key-knowledge-filter` 的区别: 本 skill 是总流程（回答"先做什么后做什么"）；key-knowledge-filter 是流程中第 2-3 步的深挖（回答"具体怎么砍内容"）
- 与 `knowledge-modeling` 的区别: 本 skill 解决"课程从无到有的流程"；knowledge-modeling 解决流程中"关键知识点如何串成模型"这一个环节
- 与 `course-title-naming` 的区别: 命名只是本流程的第 4 步；已建好课只缺名字时直接用 course-title-naming

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **澄清课程目标（不可跨越）**
   - 问用户："这门课希望学员学完后**做什么**（不是知道什么）？成为什么样的人？"
   - 用一句话逻辑写出：学习目标 = 工作行为 + 成为的角色
   - 完成标准: 学习目标可写出且不含"了解/理解/掌握知识"类纯认知动词，含明确工作行为
   - 判停条件: 若用户说不清目标，先用"你希望学员健康还是漂亮"式二选一追问收敛；目标未定，禁止进入下一步

2. **MECE 罗列知识点**
   - 引导用户穷尽罗列，此步**禁止筛选**；建议头脑风暴，条件允许邀请相关岗位的明星员工参与
   - 用三要求检查：穷尽（没有遗漏）/ 独立（边界清晰不重叠）/ 衔接（关系有逻辑）
   - 完成标准: 知识点清单通过三要求检查，通常 10-20 个

3. **选择关键知识点 + 结构化**
   - 调用 `key-knowledge-filter` 的三指标打分法收敛到 ≤6 个（最多 8 个）
   - 调用 `knowledge-modeling` 把选出的关键知识点串成课程模型
   - 完成标准: 产出"≤8 个关键知识点 + 一个可命名的课程结构/模型"

4. **撰写课程主题（最后一步）**
   - 调用 `course-title-naming` 的三点式标准命名
   - 完成标准: 主题符合痛点/焦点/利益点之一，且与第 1 步的学习目标一致（不一致说明目标已漂移，回到第 1 步）

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **课程已成熟，只缺教学呈现设计** — 四步骤是"课程设计"（科学），不是"教学设计"（艺术）；已有内容要讲得更精彩，用成人教学设计八段锦
- **目标是知识普及而非行为改变** — 本流程强绑定"以绩效为基础"，纯兴趣讲座不必动用
- **时间不允许走完流程的救急场景** — 四步骤是严谨流程，明天就要讲课时只能借用第 1 步（定目标）保命

### 作者在书中警告的失败模式

- **跳过定目标直接堆知识点**："为了培训而培训"——课程热闹但学员课后行为不变
- **一开始就定课程主题**：主题是最后一步；先起名会被名字绑架内容（减肥课学员若不改主题，就会继续讲"吃减肥药"）
- **关注行为而非目标**：执行清单全做了但关键动作漏了——2% 的遗漏造成 100% 的差距
- **把敏捷当目的**：砍内容是为了降低学习代价、快速达成目标，不是为了短而短

### 作者的盲点 / 时代局限

- **流程被讲得太线性**：真实设计是迭代的——结构化时才发现目标定错了要回退。对初学者，线性流程是脚手架；熟手应允许回旋
- **一句话目标装不下复杂岗位**：管理者类课程目标多元，"工作行为+成为的角色"可能收敛过度，可补充"观—为—得"收益逻辑（本书第五章）
- **AI 时代的执行加速**：罗列知识点、起草主题可由 AI 辅助，但"判断关键性""锚定业务目标"仍是人的工作

### 容易混淆的邻近方法论

- **成人教学设计八段锦**: 解决"已知讲什么，怎么讲得有效"（教学流程设计）；本 skill 解决"讲什么"（课程内容设计）。先四步骤，后八段锦
- **ADDIE 等经典 ISD 模型**: 更重更全；四步骤是敏捷版，优势是快且聚焦关键

# 关键知识点筛选法

## R — 原文 (Reading)

> "通常情况下，每个课程都有十几个甚至更多的可以讲授的知识点。最关键或最能代表岗位水平的只是其中少数的几个关键知识点。根据二八定律，我们要从众多知识点中找到20%的可以达成80%学习目标的知识点，这才是关键。"
>
> — 王志刚, 第七章「计划课程四步骤·第三步」

---

## I — 方法论骨架 (Interpretation)

内容取舍不靠"我觉得重要"，靠一套可复算的筛选流水线，三步：

**第 1 步：先把池子做对（MECE 罗列）**
- 穷尽：先把所有可能的知识点全列出来，禁止边列边筛——先站老鹰视角看全貌
- 独立：知识点之间边界清晰，互不交叉重叠
- 衔接：厘清知识点之间的关系，使之有逻辑（作者对经典 MECE 的增补）
- 建议头脑风暴 + 邀请相关岗位的明星员工参与（能挖出珍贵的一线信息）

**第 2 步：校准颗粒度**
- 知识点颗粒度 = 知识点拆分的最小单位，具有**相对性**：颗粒度与课程时间强相关（半天课配大颗粒，两天课配细颗粒）
- 不是越细越好；颗粒度不可变而时间不够时，"少就是多"——只讲最重要的颗粒

**第 3 步：三指标打分收敛**
- 三个指标（定义有精确边界，见 GLOSSARY）：
  - **重要性** = 对绩效的影响 + 对其他任务的影响
  - **难度** = 内容之间的相对难度（不是"对某个人的难度"）
  - **频率** = 既定时间段（如年度）内的执行次数
- 打法：每个指标单独对所有知识点做 1-N 排序（**单项评价，禁止综合评价**）；三个指标的排序方向必须统一；可加权重系数（如 重要性×3、难度×3、频率×1）
- 汇总得分取头部：**关键知识点一般不超过 6 个，最多不超过 8 个**

## A1 — 书中的应用 (Past Application)

### 案例 1: 客服主管课程 12 → 6
- **问题**: 门店一线客服主管培训，6 小时，目标是"掌控基本客服技巧和管理理念，成为令客户满意的客服主管"；罗列了 12 个知识点
- **方法论的使用**: 主管先对重要性排序，再分别对难度、频率排序，三个指标乘以权重系数汇总总分，按总分取头部
- **结论**: 筛出 6 个关键知识点（主管角色认知、接待流程、跟踪服务、投诉流程等），随后被串成"客服模型"
- **结果**: 课程从"什么都讲一点"变成聚焦关键，且为后续结构化提供了输入

### 案例 2: HPTTT 课程只讲 2 小时
- **问题**: 好友邀请作者讲 HPTTT，只给 2 小时，却希望"完整讲完"四大原则、人脑机制、八段锦、四步骤等全部内容
- **方法论的使用**: 作者判断颗粒度不可变而时间极短，按"少就是多"只选最重要的一个颗粒——四大原则
- **结论**: 讲完全部 ≠ 学员得到全部；2 小时讲透四大原则让学员能举一反三
- **结果**: 学员用"颠覆思维"形容这 2 小时，培训改变了他们很多固有观念

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 课程设计到一半，发现内容远超课时，必须砍但砍不动
2. 业务方/专家说"这些都很重要，都要讲"，需要一套客观方法顶住压力
3. 工作坊中，学员捧着 15 个知识点问"老师，哪个该留？"
4. 旧课程改造：内容臃肿、学员负担重，需要收敛
5. 学员把内容拆得很细很全来"求认可"——此时要做颗粒度与课时的匹配诊断，而非附和他的"专业"

### 语言信号 (用户的话里出现这些就应激活)

- "内容太多，讲不完怎么办"
- "这些都很重要，怎么取舍/怎么砍"
- "帮我筛选/排序这些知识点"
- "课时只有 X 小时，怎么装"
- "我拆得很细/内容很全，够专业了吧"（颗粒度求诊）
- "prioritize / too much content / 二八定律 / 关键知识点"

### 与相邻 skill 的区分

- 与 `plan-course-4-steps` 的区别: 本 skill 是四步骤中第 2-3 步的深挖操作手册；不知道整体设计流程时先用 plan-course-4-steps
- 与 `knowledge-modeling` 的区别: 本 skill 负责"选出哪些点"（收敛）；knowledge-modeling 负责"把选出的点串成模型"（组织）。先筛选，后结构化

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **检查罗列质量（MECE 三要求）**
   - 拿到用户的知识点清单，逐条核对：穷尽（有明显遗漏吗？可用"还有吗"追问 + 建议邀请明星员工补盲）/ 独立（有交叉重叠吗？合并）/ 衔接（关系清楚吗？）
   - 若用户还没有清单：先引导穷尽罗列，此步禁止筛选
   - 完成标准: 清单通过三要求检查
   - 判停条件: 若内容是**流程类知识点**（操作步骤不可更改），跳过第 3 步直接按流程组织；若是**固化知识点**（如法规），仍走完整筛选，未选中的用读书打卡等混合式学习落地

2. **校准颗粒度**
   - 问清课程时长，判断当前颗粒度是否匹配（半天→大颗粒；1-2 天→细颗粒）
   - 颗粒度不可变而时间不够时：执行"少就是多"，只保留最重要的颗粒
   - 自检金句："这些内容是学员需要的，还是你认为他们需要的？"
   - 完成标准: 清单颗粒度与课时匹配

3. **三指标单项排序打分**
   - 造表：列 = 知识点 / 重要性 / 难度 / 频率；对每个指标单独做 1-N 排序（N=知识点数）
   - 三指标排序方向必须统一（如统一"数字大=更重要/更难/更频繁"）
   - 与用户确认权重（默认 重要性×3、难度×3、频率×1；频率不重要时调低）
   - 完成标准: 每个知识点有 3 个排序分，且用户认可排序依据
   - 注意: 难度 = 内容间相对难度（禁止代入"小张觉得难"）；频率 = 时段内执行次数（禁止代入"几个人做"）

4. **加权汇总并截取**
   - 计算总分 = Σ(排序分 × 权重)，按总分降序，取 Top 6（最多 8）
   - 向用户展示被砍掉的清单及理由（打分表就是和业务方沟通的证据）
   - 完成标准: 产出 ≤8 个关键知识点 + 完整打分表（审计用）
   - 下一步: 调用 `knowledge-modeling` 把选出的点串成模型

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **知识点清单还不存在** — 先罗列（plan-course-4-steps 第 2 步），没有池子无从筛选
- **流程类不可拆内容** — 作者明确：流程类知识点无法更改时跳过筛选，直接按流程讲
- **学习目标还没定** — 重要性 = 对绩效（目标）的影响；目标未定，打分无锚。先定目标

### 作者在书中警告的失败模式

- **综合评价而非单项排序**：三个指标混着感觉打，等于没打——必须一次只评一个维度
- **三指标方向不统一**：重要性里 12 分=最重要，难度里 12 分却=最简单，汇总即错乱
- **指标概念误用**：把"难度"理解成对某个执行者的难度、把"频率"理解成几个人做——打分全错
- **颗粒度与时间错配**：2 小时想讲完整个 HPTTT 体系——念得完，但学员记不住更别说应用

### 作者的盲点 / 时代局限

- **"精确的虚假感"风险**：1-N 排序 × 权重看似量化，但重要性排序本身仍是主观判断，只是被形式化了。打分表的价值是"让分歧可讨论"，不是"让答案客观"——业务方与讲师排序不一致时，应对齐讨论而非各算各的
- **明星员工参与的前提被低估**：明星员工的隐性知识未必能言传，"邀请参与"不等于"能挖出来"，经验萃取本身是一门手艺
- **AI 可加速**：AI 可辅助罗列和初步打分，但权重设定与最终截取必须人来定

### 容易混淆的邻近方法论

- **经典 MECE（麦肯锡）**: 公共知识；作者的增补是第三条"衔接"与"先穷尽禁止筛选"的顺序约束
- **艾森豪威尔矩阵（重要/紧急四象限）**: 面向个人事务管理；本方法是面向课程内容的三指标排序，多了"难度"与"频率"且要求单项排序

## 1. 结构 (Structural)

### 类型
实操手册式的方法论章节 (培训师课程设计的科学流程)

### 一句话主旨
课程设计是一门科学——以"关注目标而非行为、关注关键工作而非全部工作"为底层逻辑，用"确定学习目标 → 罗列知识点 → 选择关键知识点 → 结构化并命名"四步骤，让学员快速胜任。

### 骨架 (主要论点及其关系)

1. **底层逻辑一：关注目标，而非行为** — 射击案例 (2% 的执行差异导致 100% 的结果差异) + 减肥课学员案例 (目标澄清连课程主题都改对了); 目标是选择一切内容的判据
2. **底层逻辑二：关注关键工作，而非全部工作** — 沟通课聚焦为"批评的沟通艺术"案例; 三大好处： 节约时间、简单有效、**快速胜任而非胜任** (销售总监 4 年路径 vs 500 强 3 个月路径的对比)
3. **计划课程四步骤** (本章主体，递进流程):
   - 第一步 确定学习目标： 收益逻辑 ("观—为—得", 详见第五章) 或一句话逻辑 (学习目标 = 工作行为 + 成为的角色); 不可跨越的一步
   - 第二步 罗列知识点： MECE 三要求 (穷尽/独立/衔接); 头脑风暴 + 明星员工参与; 知识点颗粒度的相对性 ("少就是多"); 固化知识点与流程类知识点的特殊处理
   - 第三步 选择关键知识点： 二八定律; 三指标 (重要性/难度/频率) 单项排序打分 × 权重系数; 关键知识点 ≤6 个 (最多 8 个); **选出后把知识点结构化/模型化** (字母/流程步骤/内容逻辑/公式四种方式)
   - 第四步 撰写课程主题： 最后才命名 (此时主题已"面目全非"); 三点式标准 (直击痛点/找到焦点/切入利益点)
4. **回顾本章** — 5 道复习题固化关键概念

**论点之间的关系**: 递进 — 两条底层逻辑是"道", 四步骤是"术"; 四步骤内部严格串行, 前一步是后一步的输入

### 作者要解决的核心问题
培训师面对一门课可以讲的十几个甚至更多知识点时，如何科学地 (而非凭感觉地) 收敛出最关键的内容并组织成易记易讲的结构，让学员以最小代价快速胜任。

## 2. 解释 (Interpretive)

### 关键术语 (作者本人的用法)

| 术语 | 作者的定义 | 和常识用法的差异 |
|---|---|---|
| HPTTT 四大原则 | 高绩效培训师的四条铁律, 本章反复引用"少就是多""不关注学员学什么, 只关注学员做什么" | 是约束课程设计每一步的价值判断标准, 不是口号 |
| 计划课程四步骤 | 确定目标 → 罗列知识点 → 选关键知识点 → 结构化+撰写主题 | 强调顺序不可跨越, 尤其"定目标"在最前、"写主题"在最后 |
| MECE (罗列知识点) | 穷尽 (全部列出不筛选) / 独立 (边界清晰不重叠) / 衔接 (厘清关系有逻辑) | 作者加了第三条"衔接", 超出经典 MECE 的两条 |
| 知识点颗粒度 | 知识点拆分后的最小单位; 具有相对性, 与课程时间强相关 | 不是越小越好——半天课配大颗粒, 两天课配细颗粒 |
| 关键知识点 | 20% 能达成 80% 学习目标的知识点; 用重要性/难度/频率三指标打分选出; ≤6 个最多 8 个 | 不是"我觉得重要", 而是三指标量化排序后胜出的 |
| 重要性/难度/频率 | 重要性=对绩效及对其他任务的影响; 难度=内容间的相对难度 (非对某执行者); 频率=既定时间段内执行次数 | 三个定义都有反常识的精确边界 (如难度不是"小张觉得难") |
| 快速胜任 | 课程设计的真正价值: 比"胜任"更进一步, 压缩到达胜任的时间 | 销售 4 年 vs 3 个月的对比; 是课程价值的衡量标尺 |
| 结构化/模型化四方式 | 字母 (SMART/GAPS/HAND) / 流程步骤 (四步曲) / 内容逻辑-金字塔 (七个习惯/导师罗盘) / 公式 (绩效=有价值的结果/行为) | 模型要有"意义钩子" (GAPS=差距); 结构化必须服务课程目标 (五行修心路反例) |
| 三点式主题 | 直击痛点 / 找到焦点 / 切入利益点 | 好莱坞大片式命名, 且是最后一步而非第一步 |

### 核心命题 (用自己的话)

1. 执行层面的微小遗漏 (2%) 会造成结果层面的巨大差距 (100%), 所以设计课程必须先盯住目标
2. 纠结哪些内容该讲时, 回到课程目标自然有答案——目标甚至会反过来修正课程主题
3. 只教对绩效影响最大的关键工作, 而不是全部工作
4. 敏捷不是目的而是手段: 减少学员学习代价, 尽快实现教学目标
5. 越简单越有效; 简单是理论深度+实践高度厚积薄发的结果
6. 课程设计的真正价值是"快速胜任"——压缩到达胜任的时间比胜任本身更有价值
7. 罗列知识点必须先穷尽后筛选 (MECE), 先站老鹰视角看全貌, 避免遗漏
8. 知识点颗粒度与课程时间匹配; 时间不够就砍颗粒, "少就是多"
9. 选关键知识点靠三指标量化 (重要性/难度/频率×权重), 单项排序再汇总, 不凭感觉
10. 关键知识点要串成结构或模型 (四种方式), 才能方便学员记忆、理解和复制
11. 结构化必须锚定课程目标——脱离目标的模型再精妙也是花架子 (五行修心路反例)
12. 课程主题是最后一步: 经历四步骤后最初的主题已面目全非, 需重新定位

### 论证链
底层逻辑 (目标导向 + 关键少数) → 四步骤流程化 → 每步配小练习固化概念 → 每个方法配"经典模型 (SMART/七个习惯/吉尔伯特) + 作者亲历案例 (GAPS/HAND/导师罗盘/四步曲)"双证据 → 用可量化的业务结果收束 (新人离职率 50%→20%、4 天课压到 2 天、流失率降 20%+)。五行修心路作为反例, 论证"结构化不能脱离目标"。

## 3. 批判 (Critical) ★

### 作者的时代局限
- 2019 年语境: AI 时代"罗列知识点""起课程名"等环节可由 AI 大幅加速, 但"判断关键性""锚定业务目标"仍是人的工作——方法论本身不过时, 执行工具已变
- 混合式学习在文中仅作为"固化知识点"的兜底处理方式提及, 未成体系

### 作者的立场盲点
- **四种结构化方式仍无显式选择标准**: 什么时候该用字母、什么时候该用公式? 文中案例暗示"跟内容特性走" (话术多→按客户表情分类; 两大模块→公式), 但没有提炼成决策规则——工作坊学员最需要这张"选择地图"
- **三指标打分有"精确的虚假感"风险**: 1-12 排序×权重看似量化, 但重要性排序本身仍是主观判断, 只是被形式化了; 作者未讨论排序分歧时怎么办 (如业务方与讲师判断不一致)

### 未被证明的假设
- 假设课程目标总能被一句话收敛 ("学习目标=工作行为+成为的角色"); 对复杂岗位 (如管理者) 目标本身多元, 一句话可能装不下
- 假设"明星员工参与头脑风暴"可得珍贵信息, 未讨论明星员工的隐性知识无法言传的常见困境 (经验萃取本身是一门手艺)

### 最强反对意见
"这套流程把课程设计说得太线性了": 真实设计是迭代的——选完关键知识点才发现目标定错了、结构化时才看清知识点之间的关系, 需要反复回退。本章把四步骤讲成单向流水线, 只在第四步提了一句"主题已面目全非", 低估了设计过程的回旋性。不过对初学者, 线性流程恰恰是最好的脚手架, 回旋是熟手的特权。

> **以上批判会直接成为下游 skill 的 Boundary (B) 字段来源**

## 4. 应用潜力 (Applicability)

### 可 skill 化的内容
- [ ] **S1 计划课程四步骤** (总流程): 目标→罗列→筛选→结构化+命名, 适合"学员要设计一门新课, 不知从何开始"
- [ ] **S2 关键知识点筛选法** (第二步+第三步): MECE 罗列 + 颗粒度判断 + 三指标打分, 适合"内容太多, 不知道砍哪些"
- [ ] **S3 知识点结构化/模型化** (第三步后半): 四种方式 + 选择逻辑 + 目标校验, 适合"关键知识点有了, 但串不成模型" ★ 用户特别提醒: 这是内容设计中非常重要且难的核心
- [ ] **S4 课程主题命名三点式** (第四步): 痛点/焦点/利益点, 适合"课设计完了, 想起个吸引人的名字"

### 不适合 skill 化的内容
- 射击案例、减肥课对话、销售成长路径对比等故事: 作为各 skill 的 R/A1 素材保留
- 第五章"观—为—得": 本章明确说"不再赘述", 文本不全, 不独立成 skill, 仅在 S1 中引用其存在
- 章末复习题: 作为 test-prompts 设计灵感保留

### 预估 skill 数量
**约 3–4 个** (用户预期 2–4; 最终由阶段 1.5 三重验证决定。S4 体量最小, 若三重验证不过则并入 S1)

### 优先级排序 (按"最能赋能普通人"的角度)
1. **S3 知识点结构化/模型化** — 用户明确: 内容设计中非常重要且难的核心
2. **S2 关键知识点筛选法** — "内容太多砍不动"是最高频卡点
3. **S1 计划课程四步骤** — 总纲, 统摄 S2/S3/S4
4. **S4 课程主题命名** — 小而美, 独立性强
